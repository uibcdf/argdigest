# 0.17.1

This patch release repairs consumer argument handling and diagnostic attribution,
and qualifies the public SMonitor nested-signal correction.

- Preserve literal keywords named like a function's `**kwargs` parameter without
  expanding them again or replacing explicitly bound arguments (#47).
- Keep unknown/missing argument errors catchable as Python `TypeError`, retaining
  their ArgDigest identities, catalog codes and contexts (#48).
- Missing optional Beartype emits one decoration-time warning without a required
  dependency error; present but broken/transitive imports propagate (#46).
- Reject ambiguous consumer digester registrations with the existing
  `DigestNotDigestedError` and dedicated `ARG-ERR-DIGESTER-001`. Identify the
  consumer, argument, digester and parameter-naming correction without formatting
  signature defaults or restricted values (#50).
  Valid callable registrations avoid diagnostic label reads; missing or unsafe
  labels cannot reject valid signatures or replace the configuration error (#53).
- Correct optional PyUnitWizard's API minimum to >=0.22.0 for fast_track (#43).
- Preserve the original MIT notice using SPDX metadata and a tested
  Setuptools >=77.0.3 backend; adopt immutable publisher v2.3.0 (#44–#45).
- Select public SMonitor 0.22.1 in full installed qualification, including nested
  signal/capture/native/catalog/application-policy controls (#49). Applications
  relying on corrected filtered/silenced-inner observation need SMonitor
  >=0.22.1. Core dependency floors remain SMonitor >=0.16.0 / DepDigest >=0.11.0.

Qualified for Python 3.11–3.14 on Linux, macOS arm64 and Windows. All twelve source cells, twelve full installed cells and twelve separate NumPy-free lower-bound cells passed. Full installed fixtures use SMonitor 0.22.1, DepDigest 0.15.1 and PyUnitWizard 0.27.0; core qualification retains SMonitor 0.16.0 / DepDigest 0.11.0. Consumer scientific acceptance remains with application owners.
