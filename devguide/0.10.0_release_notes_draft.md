# ArgDigest 0.10.0 — Release Notes Draft

**Status:** draft. **Theme:** the function argument contract (axis 1).

**This release contains a deliberate breaking change**, taken before `1.0.0` by explicit
release-owner decision on 2026-08-07, superseding the `0.7.x` exit criterion that no
breaking change would land before the stable tag. The reasoning is in the
[roadmap note](ROADMAP.md) and summarized below.

## Why

ArgDigest covered one axis: *given an argument name, is its value valid and in canonical
form?* That is what argument digesters do, and they do it well.

It had no way to express the other one: *may this function receive this argument at all,
and does it have what it needs?* With nowhere to live, function-dependent rules lodged
inside per-argument digesters — 102 of MolSysMT's 392 digesters branch on `caller` — so
the argument contract of a function was never written down in one readable place.

The visible symptom was worse than untidy. `bind_arguments` discarded any keyword a
closed signature did not declare, before any policy layer could see it. A mistyped
argument therefore ran with the default and returned a plausible wrong answer:

```python
msm.extract(molsys, selection='all', structure_indices=[0, 1, 2])   # 3 structures
msm.extract(molsys, selection='all', structure_indeces=[0, 1, 2])   # 5000, no diagnostic
```

**ArgDigest was more permissive than the language it wraps.** Plain Python raises
`TypeError` for an unexpected keyword. Stabilizing `1.0.0` on top of that would have
frozen the anomaly into the contract every downstream library depends on, which is why
this could not wait for `1.1`.

## What is new

- `FunctionContract` — what a function accepts and requires, declared as data:
  `admits`, `requires_any_of`, `mutually_exclusive`, `co_required`.
- `Domain` — a named, introspectable set of admissible keyword names, so a function
  taking 118 attribute names through `**kwargs` can declare its real domain once.
- `describe_contract` — renders a contract as plain data. The accepted domain of a
  `**kwargs` function is invisible to `inspect.signature`; this makes it readable again.
- `FUNCTION_SOURCE` and `DOMAIN_SOURCE` configuration, discovered exactly like argument
  digesters, so a consumer learns no second idiom.
- `unknown_argument` policy: `"error"` (default), `"warn"`, `"ignore"`, overridable per
  consumer and per function.
- Catalogued diagnostics: `UnknownArgumentError` (`ARG-ERR-CONTRACT-001`),
  `MissingArgumentError` (`ARG-ERR-CONTRACT-002`), `ArgumentConsistencyError`
  (`ARG-ERR-CONTRACT-003`), `FunctionContractWarning` (`ARG-WARN-CONTRACT-001`), with
  near-miss suggestions.

## Breaking change

`unknown_argument` defaults to `"error"`. A call passing a keyword outside a function's
contract now raises instead of being silently ignored.

Two properties bound the blast radius:

- A **closed signature** is held to its own parameters, which restores what Python
  already did. No declaration is needed and none of the previously *working* calls
  change.
- A function declaring `**kwargs` admits anything until its domain is declared, so no
  consumer is broken by a domain it has not written yet.

Set `UNKNOWN_ARGUMENT = "warn"` in the consumer config module for a transition period,
or `"ignore"` to restore the previous behaviour exactly.

## Migration

Nothing is required. Both first-party consumers passed with no change on their side.

To adopt the axis, a consumer adds three configuration lines and declares data:

```python
# mylib/_argdigest.py
FUNCTION_SOURCE = "mylib._private.argdigest.function"
DOMAIN_SOURCE = "mylib._private.argdigest.domain"
UNKNOWN_ARGUMENT = "error"
```

```python
# mylib/_private/argdigest/domain/attribute.py
from argdigest import Domain
from mylib.attribute import attributes, is_attribute

domain = Domain(name='attribute', contains=is_attribute, members=lambda: tuple(attributes))
```

```python
# mylib/_private/argdigest/function/get.py
from argdigest import FunctionContract

contract = FunctionContract(caller='mylib.basic.get.get', admits='attribute')
```

Pointing the domain at the library's own catalogue, rather than copying names into a
list, is what keeps the two from drifting apart.

## Delegating domains

`Domain(depends_on=..., by_value=...)` declares the admissible set per value of another
argument, keyed by one name or a tuple. It stays data, so `describe_contract` renders the
table.

A value with no entry means **cannot decide**, not **refuse**: the argument carrying it is
about to be rejected by its own digester, which names the real problem.

`by_value` takes any `Mapping`, so a table too large to write out can compute itself
lazily. `molsysmt.basic.convert` does exactly that across 89 target forms and 561 edges,
at 2 µs per call once warm.

The limit is the key, not the size: it must be an argument, cheap to read. `convert`'s
exact set depends on `(origin, target)`, and deriving the origin costs about 14% of a
conversion, so it keys on the target alone and accepts the union across origins — 4.9
names on average where the exact set is 3.3, against *anything* before.

## Evidence

| Suite | Result |
| --- | --- |
| ArgDigest | 122 existing + 26 new tests pass |
| MolSysMT | ~8300 tests with `UNKNOWN_ARGUMENT = "error"`; fast release gate 12/12; Ruff clean |
| MolSysViewer | 1296 tests, nothing declared on its side, zero contract errors |

That both consumers passed without changing a call is the expected shape of the defect:
it never troubled the code that was written against the API, only the people using it.

## Follow-up

- Migrating the `caller`-branching rules out of per-argument digesters and into contracts
  is a separate, larger piece of work. Not all 102 should move: a digester needing
  `syntax` to interpret a selection is value digestion with context, and belongs where
  it is.
- Consider flipping MolSysMT's redundant explicit `UNKNOWN_ARGUMENT = "error"` to a
  comment once the default is proven in the wild.
