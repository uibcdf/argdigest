# 0.14.0 release notes

ArgDigest 0.14.0 makes scientific dependencies optional and improves decorated
method validation. Python 3.11–3.14 remains supported.

## Changes

- Core installation and standard pipelines no longer require or load NumPy.
  Install `argdigest[science]` for NumPy pipelines, or declare NumPy directly in
  a scientific consumer. `argdigest[pyunitwizard]` includes NumPy and PyUnitWizard.
- Only the literal boolean `True` bypasses digestion. Strings such as `"yes"`
  and integers such as `1` now follow normal argument validation.
- Both decorator orders work for classmethods; their `cls` receiver is excluded
  from argument digestion. A free-function argument called `cls` is still digested.
- Digesters may accept optional `qualname` to identify the runtime class and
  method. Existing `caller` registry keys remain unchanged.
- Contract refusals expose their cause and allowed arguments more clearly.
- Creating a PyUnitWizard adapter or pipeline factory defers provider loading
  until an operation executes. Missing-provider catalog diagnostics and original
  transitive import failures remain preserved.

## Migration

Pass `skip_digestion=True` explicitly when bypass is intended; replace truthy
strings/integers. Scientific consumers must declare their NumPy dependency or
install the science extra. Existing digesters need no signature change unless
they want runtime method identity through `qualname`.

Core dependency floors remain DepDigest 0.11.0 and SMonitor 0.16.0. The release
uses staging, full source/installed matrices and minimal-core installed checks.
Public promotion preserves the tested file's SHA-256. Zenodo archival is checked
independently and covers the source snapshot, not the Conda package.
