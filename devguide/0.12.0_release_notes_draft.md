# 0.12.0 — release notes draft

**Status:** draft. Unreleased; `main` is `0.11.0` plus the commits below.
**Shape:** one defect fix and two deliberate breaking changes, both taken pre-`1.0.0`
for the same reason `0.10.0` took its own: it is cheaper now than after.

---

## Fixed — a decorated function is called back the way it was declared

A function taking `*args` could not be carried by `@arg_digest`. Any positional call
raised, and a keyword-only caller saw nothing, which is how it reached a released
library unnoticed. Reported from MolSysViewer against `0.11.0`.

The cause was one line used twice: the wrapped function was called back with
`fn(**bound)`. Digestion works on a flat `name -> value` mapping, which is what makes a
digester reachable by argument name, but a var-positional parameter has no keyword form
and a positional-only one refuses to be named. **The report suspected positional-only
was broken the same way. It was, and the same change fixes both.**

```python
@arg_digest()
def combine(*items, tag=None):
    return items

combine("a", "b")     # 0.11.0: TypeError.  0.12.0: ('a', 'b')
```

`core/utils.build_call` reconstructs the call shape from the signature, and
`DigestionPlan.requires_call_shape` decides once at decoration time whether a signature
needs it — so a signature with neither `*args` nor `/` keeps the single dict unpack it
had and pays nothing.

**Semantics now written down** (`SPEC.md` §4.4, canonical guide §5): `*args` is bound as
a single tuple and digested **once**, under the parameter's own name. A digester for
`def combine(*items)` receives `('a', 'b')`, not `'a'` and then `'b'`. That is what lets
it assert something about the group, but it means the digester is written against a
collection.

*Consumers:* MolSysViewer can retire its exemption test and re-decorate the callables it
had to leave undigested.

## Breaking — `requires-python` is now `>=3.11,<3.14`

It said `>=3.10`, and nothing else in the repository agreed: the README badge, both CI
matrices and the conda build all said 3.11 to 3.13. The declaration was not merely
optimistic but impossible to honour — the test suite imports `tomllib`, stdlib only
since 3.11, so 3.10 could not even be tested.

The upper bound is closed on purpose. An open one promises support for a Python that has
never been run against, which is the promise `requires-python` is least able to keep.

`tests/test_compatibility_matrix.py` now derives the range from the versions actually
tested and holds `pyproject.toml`, both workflows, the conda build, the README badge and
the compatibility page to it, so adding a version to the matrix forces the bound to move
with it.

*Consumers:* pip refuses to install on 3.10 and 3.14 instead of installing something
untested. No consumer in the suite was on either.

## Breaking — `ValidatedPayload` is removed, not replaced

The passport had two live defects. It was declared twice — in `core/contract.py` and
again in `contrib/pyunitwizard_support.py` — so the decorator's `isinstance` could never
match a payload the PyUnitWizard pipelines emitted, and the wrapper reached the function
body in place of the array. And it was honoured by argument **name** alone, carrying no
record of *which* verification it represented, so a claim issued by one library's
digester silenced another library's digester for the same name.

Both follow from its shape rather than from bugs in its code. The container changed the
value's type, so it had to be unwrapped before the body ran, so it stopped travelling at
the first body it met — a value passing through five nested calls was re-digested four
times anyway.

**A replacement was designed, built and measured, and declined.** Certifying the value by
identity, with the claim bound to the digester that issued it, closed both defects and
travelled where the wrapper could not, at 3.5 µs to issue and 0.46 µs to consult. It was
declined because it asked every digester author to learn three concepts for a problem no
consumer had: measured across MolSysMT, MolSysViewer and PyUnitWizard, the passport had
zero users. It is preserved with its code in
[`pending_proposals/value_certification/`](pending_proposals/value_certification/README.md),
with the conditions for reconsidering it.

The root cause turned out to be elsewhere: a digester cannot cheaply short-circuit
because asking PyUnitWizard whether a quantity is already in nanometers costs 363 µs
where the pint attribute underneath answers in 0.88. Filed as `uibcdf/pyunitwizard` →
`devguide/pending_proposals/cheap_canonicity_predicate.md`.

### Migration

| Removed | Use instead |
| --- | --- |
| `argdigest.core.contract.ValidatedPayload` | `skip_digestion=True` on internal calls |
| `sci:nm_float64_payload` | `sci:nm_float64` — returns the array, not a container |
| `sci:ps_float64_payload` | `sci:ps_float64` |
| `sci:kelvin_float64_payload` | `sci:kelvin_float64` |
| `sci:unwrap_validated_payload` | nothing — there is no container to unwrap |

`skip_digestion` was always the cheaper tool: 1.8 µs against the decorator's ordinary
path, and 7.5 µs against 65.6 on a real digester.

**Never on a public API boundary.** And if digestion dominates an operation, find out why
before bypassing it — the one case measured in this ecosystem was a digester sitting on
an internal predicate called 434 times per user action
([uibcdf/molsysmt#147](https://github.com/uibcdf/molsysmt/issues/147)), which no bypass
would have fixed.

*Consumers:* MolSysMT removed its usage in `2eca46926` before this landed, which was
required — discovery is package-style, so the missing module would have broken every
call. No other consumer referenced it.

## Also

- Removing the passport protocol took the per-call `isinstance` scan over every bound
  argument out of the hot path: the decorator's plumbing measures **18.97 µs**, down
  from 21.6.
- `devguide/` gained `solved_bugs/`, and `index.md` now says what each report folder is
  for — both were invisible to anyone who did not list the directory.
- The three pending proposals are settled: the profile-coupled bypass declined on
  measurement, the stub compiler kept for post-`1.0.0`, the bridge validator moved out of
  scope.
